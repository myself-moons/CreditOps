# CreditOps — Data Disclosure

## What is the dataset?

CreditOps is trained on the **"Credit Card Transactions Fraud Detection Dataset"** published by
Kartik Shenoy (kartik2112) on Kaggle under the CC0 1.0 Public Domain Dedication license.

- **Kaggle page:** https://www.kaggle.com/datasets/kartik2112/fraud-detection
- **License:** CC0 1.0 Universal (Public Domain Dedication) — as stated on the Kaggle dataset page.
- **Files used:** `fraudTrain.csv` and `fraudTest.csv`

## How was the data generated?

The dataset was generated using the **Sparkov Data Generation** tool (GitHub: namebrandon/Sparkov_Data_Generation).
Sparkov is a Python-based synthetic transaction simulator that:
- Simulates 1,000 fictitious customers (profiles including name, address, card number, DOB, job, etc.)
- Simulates 800 fictitious merchants (location, category, fraud tendency)
- Generates credit card transactions for each customer across a defined time window
- Labels transactions as fraudulent based on configurable fraud profiles

The simulation ran over January 2019 to December 2020. The fraud patterns are determined
by the simulation parameters — they do not reflect real-world fraud statistics.

## What conclusions can this data support?

**Can support:**
- Demonstrating MLOps pipeline architecture (DVC, MLflow, FastAPI, monitoring)
- Evaluating different model types (Logistic Regression, Random Forest, XGBoost) on an imbalanced classification task
- Illustrating temporal split methodology and PR-AUC evaluation
- Measuring how stationary a simulated distribution is

**Cannot support:**
- Claims about real-world fraud detection performance
- Generalisation to real credit card fraud patterns
- Conclusions about specific fraud categories or amounts in the real world
- Any regulatory or compliance use case

## Are real cardholders involved?

**No.** All customer profiles (names, addresses, card numbers, dates of birth, occupations) are
synthetically generated. No real financial data is used. All merchant information is also synthetic.

## How CreditOps uses the data

1. Raw CSV files are tracked with DVC (not committed to Git).
2. The full dataset is concatenated and split **temporally** (70% train / 15% val / 15% test).
3. PII-like fields (card number, name, street address, transaction ID, ZIP) are dropped before training.
4. Derived features (age at transaction, haversine distance, hour of day) replace raw fields.
5. The trained model is served via FastAPI for demonstration purposes only.
6. All API responses include a `"data_provenance": "synthetic/simulated (Sparkov)"` field.
